# ADR-007. 수집 멱등성: requestId가 아닌 eventId

상태: 채택

## 맥락
네트워크 재시도로 같은 이벤트가 두 번 올 수 있다. 중복 저장은 이력을 오염시키고 카운터를 부풀린다.

## 대안
- `requestId`로 중복 제거: 한 HTTP 요청에서 서로 다른 에러가 여러 번 나는 것이 정상이므로 정당한 이벤트를 버리게 된다. 안 보내는 클라이언트도 많다.
- 중복 허용: 카운터 과대 → 오탐.
- 클라이언트 생성 `eventId`(UUID) + `UNIQUE(project_id, event_id)` (채택).

## 결정
`eventId`가 오면 UNIQUE 위반 시 200 `duplicate:true`로 응답하고 카운터를 증가시키지 않는다. 없으면 서버가 생성하므로 그 클라이언트는 재전송 중복을 감수한다(명시). `request_id`는 추적 조회용 인덱스로만 둔다.

## 결과
- 단점: 인덱스 하나 추가(삽입 비용). 실험 C에서 인덱스 유무 삽입 p95를 비교해 정당화.
