# ADR-006. 감지 기준 시각: received_at(서버 시계)

상태: 채택

## 맥락
이벤트에는 클라이언트가 찍은 `occurred_at`과 서버가 찍은 `received_at`이 있다. 감지·추이·인덱스의 시간축을 하나로 정해야 한다.

## 대안
- `occurred_at`: "실제로 언제 났나"를 반영. 그러나 클라이언트 시계 편차·미래 시각·지연 도착이 과거 버킷을 바꾸고, Redis 버킷(서버 시각)과 정의가 달라져 두 경로 결과가 어긋난다.
- `received_at`(채택): 서버 단일 시계. 지연 도착 이벤트는 "지금 도착한" 것으로 현재 급증에 기여한다(과거 창에 소급해도 이미 지나간 창은 감지되지 않는다).

## 결정
인덱스·Redis 버킷·fallback COUNT·추이 그래프 모두 `received_at`. `occurred_at`은 상세 화면·근본 원인 분석용으로 저장만 한다. fallback 쿼리 기준 시각은 DB `NOW()`가 아니라 앱이 계산해 파라미터로 넘긴다(Redis 경로와 같은 시계).

## 결과
- 단점: 대량 재전송(백필) 시 과거 에러가 "지금" 급증으로 보인다 → 백필은 별도 API Key/환경으로 격리하거나 정책 비활성화 후 수행(운영 가이드).
